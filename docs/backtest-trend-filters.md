# ATR 단일 진입 백테스트: 추세 필터 참고서

이 문서는 `swing-atr` 전략이 매수 후보를 만들기 전에 적용하는 추세 필터의 **현재 구현 기준**을 기록한다. 백테스트 결과를 해석하거나, 전략을 수정·확장할 때 이 문서를 기준점으로 사용한다.

## 한눈에 보기

매수 신호는 일봉 종가 기준으로 계산한다. 아래 세 조건을 **나열된 순서대로 모두 통과**해야 ATR 매수 구간(`EntryPlan`)이 만들어진다.

```text
일봉 종가 확정
  -> 장기 SMA 기울기 양수인가?
  -> 종가가 장기 SMA와 최소 이격도를 충족하는가?
  -> 단기 SMA가 장기 SMA보다 높은가?
  -> ATR 매수 구간 생성
  -> 다음 거래일 5분봉에서 매수 체결 가능 여부 확인
```

기본 설정은 다음과 같다.

| 설정 | 기본값 | 뜻 |
| --- | ---: | --- |
| 장기 이동평균 기간 (`SmaPeriod`) | 120거래일 | 장기 추세와 기준 SMA |
| 기울기 비교 기간 (`SmaSlopeLookbackDays`) | 5거래일 | 현재 장기 SMA와 비교할 과거 시점 |
| 최소 SMA 이격도 (`MinimumSmaDistancePercent`) | 1% | 종가가 장기 SMA 위에 있어야 하는 최소 비율 |
| 단기 이동평균 기간 (`ShortSmaPeriod`) | 20거래일 | 최근 추세를 확인할 SMA |
| ATR 기간 (`AtrPeriod`) | 14거래일 | 매수 구간·익절·손절 폭 계산의 기준 |

UI의 정확한 명칭은 **최소 SMA 이격도**다. “최고 SMA 이격도”는 상한을 두는 값처럼 들릴 수 있지만, 현재 구현은 종가가 장기 SMA보다 *최소한 얼마나 높아야 하는지*를 검사한다.

## 필터별 계산식과 해석

### 1. 기울기 비교 기간: 장기 SMA가 상승 중인가

현재 장기 SMA와 `SmaSlopeLookbackDays` 거래일 전 장기 SMA를 비교한다.

```text
현재 장기 SMA = 최근 SmaPeriod개 종가의 평균
과거 장기 SMA = 현재 시점보다 SmaSlopeLookbackDays일 앞선 구간의
                SmaPeriod개 종가의 평균

통과 조건: 현재 장기 SMA > 과거 장기 SMA
```

같거나 낮으면 `LongSmaSlopeNotPositive`로 거절한다. 즉, “상승 중”은 0보다 큰 기울기만 의미하며 보합은 통과하지 않는다.

- 기본값 5일은 최근 5거래일 사이에 장기 추세가 위를 향했는지 확인한다.
- 기간을 줄이면 최근 변화에 더 민감해져 신호가 늘 수 있다.
- 기간을 늘리면 일시적 반등을 덜 받아들이고, 더 지속적인 상승 추세만 남긴다.

### 2. 최소 SMA 이격도: 종가가 장기 SMA 위에 충분히 있는가

당일 종가와 현재 장기 SMA를 비교한다.

```text
필요 종가 = 현재 장기 SMA × (1 + MinimumSmaDistancePercent / 100)

통과 조건: 당일 종가 >= 필요 종가
```

기본값 1%에서는 종가가 장기 SMA보다 1% 이상 높아야 한다. 정확히 1% 높은 경우는 통과하고, 그보다 낮으면 `MinimumSmaDistanceNotMet`으로 거절한다.

- `0%`: 종가가 장기 SMA와 같아도 이 조건은 통과한다. 단, 나머지 두 필터는 별도로 통과해야 한다.
- 값을 높이면 장기선 위에서 더 강하게 올라선 종목만 남아 신호 수는 줄어드는 경향이 있다.
- 이 값은 과열을 제한하는 “최대 이격도”가 아니다. 과도한 상승을 제외하려면 별도의 최대 이격도 규칙을 추가해야 한다.

### 3. 단기 이동평균 기간: 최근 흐름도 장기 흐름보다 강한가

최근 `ShortSmaPeriod`개 종가의 평균과 현재 장기 SMA를 비교한다.

```text
단기 SMA = 최근 ShortSmaPeriod개 종가의 평균

통과 조건: 단기 SMA > 장기 SMA
```

같거나 낮으면 `ShortSmaNotAboveLongSma`로 거절한다. 기본값은 20일 SMA가 120일 SMA보다 높아야 한다는 뜻이다.

- 기간을 줄이면 최근 가격 변화를 빠르게 반영하지만, 횡보 구간의 잡음에도 반응하기 쉽다.
- 기간을 늘리면 신호는 늦어지지만 더 완만하고 안정적인 최근 추세를 요구한다.
- 이 조건은 단기선이 장기선 위에 있는지만 판단한다. 두 선의 교차가 *오늘 발생했는지* 또는 단기선의 기울기가 양수인지는 현재 검사하지 않는다.

## 필요한 일봉 수

전략은 다음 값 중 가장 큰 수만큼의 일봉이 있어야 신호를 계산한다.

```text
max(SmaPeriod + SmaSlopeLookbackDays, ShortSmaPeriod, AtrPeriod)
```

기본값에서는 `max(120 + 5, 20, 14) = 125`이므로 최소 125거래일의 일봉이 필요하다. 데이터가 부족한 초기 구간은 신호를 만들지 않으며, 추세 필터 미충족 진단도 남기지 않는다.

## 백테스트에서의 신호와 체결 순서

추세 필터 통과는 즉시 매수 체결을 의미하지 않는다.

1. 당일 일봉 종가로 필터와 ATR을 계산한다.
2. 통과하면 종가를 중심으로 `± BuyBandAtrMultiplier × ATR`의 매수 구간을 예약한다. 기본값은 `±0.5 ATR`이다.
3. 다음 거래일의 5분봉에서 해당 매수 구간에 가격이 닿는지 확인해 체결을 재현한다.
4. 5분봉 시가가 구간 안이면 시가 체결, 구간 밖에서 시작해 구간을 통과하면 구간 경계 가격으로 체결한다.
5. 다음 거래일에 구간에 도달하지 않으면 `BuyBandNotReached`, 5분봉이 없으면 `MissingIntradayData` 진단을 남기고 그 예약은 취소한다.

매수 뒤에는 실제 체결가와 ATR로 익절·손절가를 만든다. 기본값은 익절 `+1.5 ATR`, 손절 `-1.0 ATR`, 최대 보유 5거래일이다. 같은 5분봉에서 진입한 경우에도 해당 봉의 종가 흐름을 반영하도록 익절·손절 판정이 수행될 수 있다.

## 결과를 읽는 방법

진단 코드가 보이면 해당 일봉이 왜 매수 후보가 되지 못했는지 알 수 있다.

| 진단 코드 | 의미 | 먼저 확인할 값 |
| --- | --- | --- |
| `LongSmaSlopeNotPositive` | 장기 SMA가 비교 기간 전보다 높지 않음 | 장기 SMA, 기울기 비교 기간 |
| `MinimumSmaDistanceNotMet` | 종가가 요구 이격도보다 장기 SMA에 가까움 | 종가, 장기 SMA, 최소 이격도 |
| `ShortSmaNotAboveLongSma` | 단기 SMA가 장기 SMA보다 높지 않음 | 단기·장기 SMA 기간과 값 |
| `BuyBandNotReached` | 필터는 통과했지만 다음 거래일 매수 구간 미도달 | 5분봉 고가·저가와 매수 구간 |
| `MissingIntradayData` | 예약된 매수일의 5분봉이 없음 | 일봉·5분봉의 날짜 대응 |

## 파라미터를 조정하는 방법

하나의 기간만 보고 최적화하지 않는다. 상승장·하락장·횡보장처럼 성격이 다른 구간을 포함한 데이터에서, 수익률뿐 아니라 거래 수·승률·Profit Factor·MDD를 함께 비교한다.

| 목적 | 조정 방향 | 예상되는 변화 |
| --- | --- | --- |
| 신호를 더 엄격하게 선별 | 기울기 비교 기간 또는 최소 이격도 증가 | 거래 수 감소, 추세 확인 강화 |
| 빠른 추세 변화를 더 빨리 반영 | 단기 SMA 기간 감소 | 신호 반응은 빨라지나 잡음 가능성 증가 |
| 완만하고 지속적인 추세만 선택 | 단기 SMA 기간·기울기 비교 기간 증가 | 신호 지연, 거짓 신호 감소 기대 |

특정 한 구간에서 가장 좋은 숫자를 만든 조합은 과최적화일 수 있다. 후보값을 소수로 제한하고, 개발·검증 기간을 나누거나 서로 다른 시장 국면에서 같은 방향의 성능이 나오는지 확인한다.

## 개발 변경 시 지켜야 할 계약

현재 구현의 기준 코드는 다음과 같다.

- 옵션의 기본값: `src/AssetPilot.Backtest/Strategy/StrategyOptions.cs`
- 필터 계산·거절 순서: `src/AssetPilot.Backtest/Strategy/SwingAtrStrategy.cs`
- 일봉 신호와 5분봉 체결의 연결: `src/AssetPilot.Backtest/Execution/BacktestRunner.cs`
- 입력값 검증과 실행 설정 복사: `src/AssetPilot.App/ViewModels/BacktestRunViewModel.cs`
- 동작 명세 테스트: `tests/AssetPilot.Backtest.Tests/SwingAtrStrategyTests.cs`

필터를 수정하거나 추가할 때는 다음을 함께 갱신한다.

1. `StrategyOptions`에 옵션과 기본값을 추가한다.
2. `RequiredBarCount`가 새 지표에 필요한 최소 이력을 포함하는지 확인한다.
3. `EvaluateAtClose`와 `ExplainNoEntry`가 같은 판정을 공유하도록 유지한다.
4. 거절 원인을 식별할 수 있는 진단 코드와 표시명을 추가한다.
5. UI 입력 검증, 실행 결과의 설정 스냅샷, 단위 테스트를 함께 추가한다.
6. 이 문서의 계산식·기본값·진단 표를 실제 코드와 맞춘다.

현재 백테스트 결과는 수수료·세금·슬리피지를 차감하지 않는다. 실제 운용 판단이나 전략 비교에 사용할 때는 이 한계를 결과와 함께 명시한다.
