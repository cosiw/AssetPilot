# KODEX 200 스윙 백테스트 설계

## 목표

KODEX 200의 일봉과 5분봉 CSV를 사용해, 일 마감 매수 신호부터 다음 거래일 매수와 익절 또는 손절 청산까지 재현하는 콘솔 백테스트를 만든다.

## 구성

- `AssetPilot.Backtest`는 시세 바, CSV 입력, 전략, 백테스트 실행 도메인을 갖는다.
- `SwingStrategy`는 옵션을 받아 신호일 종가가 단순이동평균보다 높은지 판단하고 신호일 ATR로 익절가와 손절가를 계산한다.
- `BacktestRunner`는 거래일별로 예약 매수 처리, 5분봉 청산 확인, 장 마감 신호 평가 순서로 실행한다. 포지션, 예약, 완료 거래, 오류와 종료 상태를 결과로 반환한다.
- 첫 버전은 WPF 실행 화면에서만 백테스트를 실행한다. 별도 CLI는 제공하지 않는다.

## 입력과 지표

제공된 일봉은 A~H 열 기준으로 `일자, 종가, 대비, 등락률, NAV, 시가, 고가, 저가` 순서다. 로더는 0번(일자), 1번(종가), 5번(F·시가), 6번(G·고가), 7번(H·저가) 열을 사용한다. 5분봉은 날짜, 시간, 시가, 고가, 저가, 종가의 열 순서를 사용해 현재 제공된 한글 헤더 및 인코딩에 의존하지 않는다. 파일은 최신순일 수 있으므로 로드 뒤 시간 오름차순으로 정렬한다.

기본 옵션은 단순이동평균 120일, ATR 14일, 매수 구간 반폭 0.5 ATR, 이익 실현 1.5 ATR, 손절 1.0 ATR이다. 매수 수량은 `floor(사용 가능 현금 × 자금 투입 비율 ÷ 체결가)`로 계산한다. ATR은 신호일을 포함한 14개 확정 일봉의 True Range 단순 평균으로 계산한다. 지표가 준비되지 않은 일봉에는 신호를 평가하지 않는다. 신호일 장 마감에 `종가 - 0.5 ATR`부터 `종가 + 0.5 ATR`까지의 매수 구간을 고정한다. 실제 체결가가 정해지면 목표가는 `체결가 + 1.5 ATR`, 손절가는 `체결가 - 1.0 ATR`으로 고정한다.

## 실행 규칙

각 거래일은 다음 순서로 처리한다.

1. 직전 장 마감에 생성된 예약을 당일 모든 5분봉에서 검사한다. 시가가 매수 구간 안이면 시가에 체결한다. 시가가 구간 아래이고 고가가 하한가에 도달하면 하한가에, 시가가 구간 위이고 저가가 상한가에 도달하면 상한가에 체결한다. 해당 거래일의 5분봉이 없으면 예약을 체결하지 않고 데이터 누락으로 기록한다.
2. 매수 체결이 있으면 그 첫 5분봉부터, 이미 보유 중인 경우에는 모든 5분봉에서 청산을 검사한다.
3. 장 마감에 포지션이 없고 당일에 장중 청산하지 않았다면, 확정 일봉으로 다음 거래일 매수 예약을 평가한다. 장중 청산한 날에는 재진입하지 않는다.

매수 전에 호가 단위 적용 후 `0 < stop < entry < target`을 검증한다. 현재 프로젝트에 재사용 가능한 호가 단위 로직은 없으므로 첫 버전은 입력 가격과 계산 가격을 decimal로 그대로 사용한다. 유효하지 않은 예약은 사유와 함께 건너뛴다. 시가에서 매수된 경우에는 해당 봉부터 청산을 검사한다. 봉 내부 경계가에서 매수된 경우에는 체결 전후 순서를 OHLC만으로 알 수 없으므로 다음 5분봉부터 청산을 검사한다.

청산은 5분봉 시가를 우선한다. 시가가 손절가 이하이면 시가 손절, 시가가 익절가 이상이면 익절가 청산이다. 둘 사이이면 고가/저가 도달을 검사하며, 같은 봉 양쪽에 도달하면 손절가에서 손절 우선으로 한 거래만 기록한다. 거래 시각은 해당 5분봉의 시작 시각이다.

## 결과와 오류

완료 거래는 신호일, 매수 시각·가격·수량, 목표가·손절가, 매도 봉·가격·사유, 비용 차감 전 손익을 보존한다. 결과에는 미청산 포지션, 미체결 예약, CSV 파싱 오류, 예약 체결일의 5분봉 누락도 포함한다. KOSPI 일봉은 이 버전에서는 읽지 않는다.

## 전략과 화면

한 번의 백테스트 실행에는 전략 하나만 사용한다. 전략 선택은 동시에 여러 전략을 실행한다는 뜻이 아니라, 그 실행에 적용할 `ITradingStrategy` 구현체를 하나 고르는 기능이다. 전략은 신호일 마감 평가와 실제 매수가 확정된 뒤의 청산 가격 계획을 제공하며, 러너는 현금·포지션·체결을 관리한다.

화면은 실행 설정, 실행 상세, 기록 목록으로 나눈다. 실행 설정에는 일봉·5분봉 파일, 전략 선택, 전략별 설정값, 시작 자금, 자금 투입 비율을 둔다. 상세의 기본 표는 완료 거래 묶음이 아니라 시간순 체결 원장으로, 매수와 매도를 각각 한 행으로 표시한다. 각 행에는 체결 시각·전략·구분·사유·가격·수량·금액·체결 뒤 평균 매수가·체결 뒤 보유 수량·매도 시 실현 손익을 표시한다.

상단에는 누적 손익과 수익률, 완료 거래 수, 승률, Profit Factor, 최대 낙폭(MDD), 최대 연속 손절, 평균 수익·손실, 미청산 수와 데이터 누락 수를 표시한다. 비용은 첫 버전에서 계산하지 않으며 모든 결과에 `비용 미반영`을 표시한다.

기록 목록은 실행일, 전략명, 설정 요약, 데이터 기간, 완료 거래 수, 승률, 누적 손익, 수익률, MDD, Profit Factor를 보여준다. 목록 행을 클릭하면 해당 실행의 상세로 이동하며, 최대 세 실행을 선택해 비교할 수 있다.

## 결과 저장

첫 버전은 기존 SQLite 저장소에 세 테이블만 추가한다.

- `backtest_runs`: 실행 한 건의 요약이다. ID, 실행 시각, 전략 키와 버전, 전략 설정 JSON, 대상 종목, 시작·종료 자금, 일봉·5분봉 파일명과 해시, 데이터 기간, 상태, 누적 손익·수익률·완료 거래 수·승패 수·Profit Factor·MDD·최대 연속 손절·데이터 누락 수를 저장한다.
- `backtest_executions`: 시간순 매수·매도 체결 원장이다. 실행 ID, 내부 포지션/거래 사이클 ID, 체결 시각, 매수/매도 구분, 사유, 가격·수량·금액, 체결 뒤 보유 수량·평균 매수가, 매도 시 실현 손익을 저장한다.
- `backtest_diagnostics`: 실행 ID, 심각도, 진단 코드, 관련 거래일, 사용자용 메시지를 저장한다.

포지션 테이블은 만들지 않는다. 포지션은 체결 원장을 시간순으로 재생해 계산한다. `backtest_executions`의 내부 거래 사이클 ID는 완료 거래 수·승률·평균 손익 계산을 위해 사용하지만 기본 화면에서 체결을 묶어 표시하지는 않는다. 날짜·ID는 ISO 8601/GUID 텍스트로, 금액·수량은 decimal 정밀도 보존을 위해 텍스트로 저장한다.

## 검증

자동 테스트는 다음을 검증한다.

1. ATR 400, 매수가 10,000에서 목표가 10,600 청산과 +600 손익.
2. 손절가 9,600일 때 시가 9,300 갭 손절.
3. 한 봉이 목표가와 손절가 모두 도달할 때 손절 한 건만 기록.
4. 장중 청산일에는 재진입하지 않지만 장 마감 신호로 다음 거래일 예약 가능.

자동 테스트는 제공된 KODEX 200 일봉과 5분봉의 실제 열 순서와 최신순 입력 정렬도 검증한다.
