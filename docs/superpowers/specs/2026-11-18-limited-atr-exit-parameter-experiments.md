# 제한적 ATR 청산 파라미터 실험 명세

## 목적

기준 전략의 진입 규칙은 고정하고, ATR 익절 배수·ATR 손절 배수·최대 보유 거래일만 바꾼 동일 조건의 백테스트를 비교한다. 이 기능은 과거 최고 수익률을 자동 채택하는 최적화기가 아니라, 사람이 전략 변경 여부를 판단할 수 있는 재현 가능한 실험 도구다.

## 기준 전략과 변경 가능 범위

다음 진입 조건은 모든 후보에서 반드시 동일하다.

| 항목 | 고정값 |
| --- | ---: |
| 장기 SMA | 120 거래일 |
| 단기 SMA | 5 거래일 |
| ATR 기간 | 14 거래일 |
| 장기 SMA 기울기 비교 | 5 거래일 |
| 최소 SMA 이격도 | 1% |
| 매수 밴드 | 0.5 ATR |
| 5분봉 매수 재확인 | 기존 체결 규칙 |

실험 후보는 다음 세 청산 값으로 한정한다.

| 항목 | 기준값 | 후보 |
| --- | ---: | --- |
| 익절 ATR 배수 | 1.5 | 1.0 / 1.5 / 2.0 |
| 손절 ATR 배수 | 1.0 | 0.8 / 1.0 / 1.2 |
| 최대 보유 거래일 | 5 | 3 / 5 / 7 |

## 실행 단계

1. **익절 단일 변수 실험**: 손절 1.0, 보유일 5를 고정하고 익절 1.0/1.5/2.0을 비교한다. 총 3개다.
2. **익절·손절 실험**: 보유일 5를 고정하고 익절·손절의 3×3 조합을 비교한다. 총 9개다.
3. **전체 청산 실험**: 세 값의 3×3×3 조합을 비교한다. 총 27개다.

후보 목록은 중복을 제거하고, 익절·손절은 0보다 커야 하며 보유일은 1 이상이어야 한다. 잘못된 후보는 전체 실험을 시작하기 전에 오류로 거부한다.

## 실행 규칙

- 모든 후보는 같은 일봉·5분봉 입력, 시작자금, 투자 비율, 데이터 기간, 거래비용 및 체결 규칙을 사용한다.
- 각 후보는 `BaselineStrategyOptions.Create(ExitStrategyOptions)`로 전략 옵션을 만들고 기존 `BacktestRunner`를 한 번씩 호출한다.
- 후보별 실행 결과에는 전략 버전, 세 청산 값, 데이터 시작·종료일, 시작자금, 투자 비율, 비용 조건을 남긴다.
- 5분봉 한 개에서 익절과 손절이 모두 닿으면 기존 손절 우선 체결 규칙을 그대로 사용한다.
- 최대 보유일은 현재 `BacktestRunner`의 강제 청산 규칙을 그대로 사용하며, 실험기가 별도 청산을 추가하지 않는다.
- 실험은 매수·매도 주문, 실거래 설정, 활성 전략 설정을 변경하지 않는다.

## 결과와 평가

각 후보 결과는 최소한 다음 값을 제공한다.

- 후보 ID와 세 청산 값
- 총수익률, CAGR, 실제 시가평가 MDD, 승률, 거래 수, Profit Factor, 평균 거래 수익률
- 평균 수익, 평균 손실, 최대 연속 손실
- 청산 사유별·월별 성과를 조회할 수 있는 개별 백테스트 실행 ID

실험 요약 CSV는 `backtest_parameter_experiment_summary.csv`로 출력한다.

```text
ExperimentId,BacktestId,StrategyVersion,StartDate,EndDate,TakeProfitAtrMultiplier,StopLossAtrMultiplier,MaxHoldingDays,TotalReturn,CAGR,MDD,WinRate,TradeCount,ProfitFactor,AverageReturn,AverageWin,AverageLoss,MaxConsecutiveLosses,Error
```

한 후보의 백테스트가 실패하면 그 후보의 오류를 결과에 기록하고 나머지 후보는 계속 실행한다. 오류 후보는 요약 CSV에 수치 열을 비우고 `Error` 열에 원인을 기록한다. 입력 데이터 자체가 비었거나 후보 목록 전체가 유효하지 않으면 실험 전체를 실패로 종료한다.

## 사람이 판단하는 원칙

- 화면과 CSV는 후보를 수치로 비교할 뿐 `추천`, `승인 대기`, `자동 적용` 상태를 만들지 않는다.
- 단일 후보의 최고 총수익률만으로 전략을 선택하지 않는다. CAGR, 실제 MDD, Profit Factor, 거래 수, 평균 손익과 인접 후보의 안정성을 함께 본다.
- 한 지점만 유난히 좋고 인접 조합이 급격히 나쁘면 과적합 가능성으로 해석한다.
- 실험 완료 후에도 기준 전략은 유지된다. 전략 변경은 사용자가 결과를 검토한 뒤 별도 작업으로 수행한다.

## 기존 자동 추천 코드의 경계

현재 `WalkForwardParameterSelector`와 월말 `ParameterDecisionStore` 흐름은 이 기능의 입력·출력으로 사용하지 않는다. 6번 구현에서는 시장 데이터 작업자가 월말에 추천을 생성하지 않도록 호출과 의존성 등록을 제거한다. 관련 클래스와 과거 승인 기록 형식은 삭제하지 않고, Walk-Forward 검증을 정식으로 재설계하는 후속 단계까지 보존한다.

## 제외 범위

- Walk-Forward 검증, 월별 자동 실행, 월간 추천 및 승인
- 실시간 또는 실거래 전략 변경
- ML/LightGBM 신호 평가
- 진입 조건·거래비용·체결 규칙 변경
- 1년 데이터를 장기 안정성의 증거로 해석하는 자동 판정

## 데이터 한계

현재 약 1년의 데이터로는 후보 간 초기 비교와 체결 규칙 검증은 가능하지만 상승·하락·횡보 시장을 모두 대표하지 못한다. 결과는 해당 표본 내 성과일 뿐이며, 3~5년 이상의 데이터와 시간 순서 Walk-Forward 검증 전에는 실전 파라미터 변경의 근거로 충분하지 않다.

## 허용 기준

1. 단계별 후보 수가 각각 3, 9, 27개이며 모든 조합이 고유하다.
2. 모든 후보는 기준 전략의 고정 진입 옵션을 공유한다.
3. 같은 입력으로 두 번 실행하면 후보 목록과 후보별 지표가 같다. 실행 ID·실행 시각만 달라질 수 있다.
4. 후보별 결과는 기존 백테스트·실제 MDD 계산·CSV 내보내기 로직을 재구현하지 않고 재사용한다.
5. 요약 CSV는 저장된 각 백테스트 실행의 결과와 일치한다.
6. 시장 데이터 작업자는 이 기능 때문에 자동 추천이나 전략 변경을 하지 않는다.

## 구현 완료 상태 (2026-11-18)

- 시장 데이터 워커의 월말 자동 추천·승인 생성 흐름을 제거했다. 기존 추천 이력 클래스는 호환성을 위해 보존한다.
- `TakeProfitOnly`(3개), `TakeProfitAndStopLoss`(9개), `AllExitParameters`(27개) 후보 생성과 기존 백테스트 러너 재사용을 구현했다.
- 후보별 백테스트 실행·실제 MDD·SQLite 실험 ID·실험 요약 CSV·수동 WPF 실행 화면을 구현했다.
- KODEX 200 일봉과 `5분봉(26년).csv` 샘플 회귀 테스트는 익절 3개 후보마다 고정 진입 조건, 5분봉 자산곡선, 실제 MDD 계산이 존재함을 검증한다. 특정 수익률 수치는 고정하지 않는다.
